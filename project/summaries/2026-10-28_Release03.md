# 2026-10-28 — SwiftKeychain 0.3.0: a label, and one prompt for a burst of reads

- **Shipped:** `KeychainItem.label` (sent as `kSecAttrLabel` on add and update, never in identity;
  `nil` leaves a stored label). `SystemKeychain(dataProtection:presenceReuse:)`,
  `maximumPresenceReuse` (five minutes), `presenceReuse`, `endPresenceReuse()`;
  `InMemoryKeychain(presence:presenceReuse:now:)` and `endPresenceReuse()`. Design:
  `project/plans/completed/2026-10-28_OnePrompt03.md`.
- **Reuse design:** opt-in; the first read's authenticated `LAContext` is passed to later reads and
  replaces; the window opens on confirmation, doesn't slide, is capped at five minutes, ends on any
  refusal or `endPresenceReuse()`; the context lives in an `OSAllocatedUnfairLock` and each presence
  call runs inside it, so a concurrent burst asks once. tvOS/watchOS: accepted, does nothing.
- **Tests:** `LabelTests` and `PresenceReuseTests`, red first (compile errors), then green. 69 with
  `--traits OAuth,CLIAuth`, 51 without (were 45 and 27).
- **Builds:** tvOS and watchOS generic builds succeed (xcodebuild; `Package.resolved` restored).
- **Docs:** guide sections "Naming an item" and "One prompt for a burst of reads"; CHANGELOG,
  README status, master plan (layout, types, decision 6, status, roadmap, Last Updated).
- **Master plan corrected:** the consumer migrations were struck through as if done; they are open
  PRs (SwiftPushInbox #1, SwiftMCPClient #4, FleetWatch #24), done when merged and checked on real
  data. The package split for older macOS recorded as declined.
- **Not verified:** a real prompt, and that the Keychain skips the second one inside a window;
