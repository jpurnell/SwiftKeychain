# 2026-10-28 — SwiftKeychain 0.1.1: the key-creation race

- **Found:** moving SwiftPushInbox's `KeychainHistoryKey` onto `KeychainKey`. Inbox handled
  `errSecDuplicateItem` by using the other launch's key; `KeychainKey.loadOrCreate` stored, and
  `store` updates on a duplicate, so the second process replaced the first's key.
- **Fixed:** `KeychainAccess.add(_:as:)` (atomic in both built-in stores; a non-atomic default
  keeps 0.1.0 conformers compiling) and `loadOrCreate` adds, then reads the winner's key.
- **Tests:** contract test for `add` on both stores; `KeychainKey` tests for the race and the
  default `add` (red first). 34 with both traits, 16 without.
- **Next:** the three migrations (SwiftPushInbox, SwiftMCPClient, FleetWatch), then 0.2.0.
